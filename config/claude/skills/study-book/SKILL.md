# /study-book — 書籍を読書マップで少しずつ勉強する

規約の正本は `/mnt/ext1/vibe-kanban/impactaky-knowledge/CONTEXT.md`(読書マップ・すり合わせ・差し替え・ストック・主張行)と `docs/adr/0004-article-layer.md`・`0006-article-replacement.md`。記事の書き方・ストック手順は /article スキルの規約に従う — このスキルは書籍特有の長期ループ(マップ管理)だけを扱う。

## 前提となる原則(すり合わせ)

エージェントはユーザが何を知っているかを、記事層と読書マップの既知マーク**からのみ**判断する。齟齬(知っているが記事層に無い)は当然存在する — 特別な埋め合わせはせず、セッション中のユーザ訂正(「それは知ってる」→既知マーク)で漸進的に写像を収束させる。

**既知確認はユーザ申告駆動**: エージェントから要素ごとに「これは既知?」と尋ねない(ポーリング禁止)。既知マークが生まれるのは初回の一括トリアージと、ユーザの自発的な「それは知ってる」だけ。デフォルトは全要素未知として扱い、いきなり内容の説明と対話に入る。

## 手順

### A. 初回 — 読書マップの初期化

1. PDF のローカルパスを受け取る。**PDFはコミットしない**。購入書籍はURLから再取得できないため、パスをマップの front matter に記録する(この repo は私的信頼境界なのでマシンパス可)
2. 目次と斜め読み(Read の pages 指定で部分読み)から**仮の要素リスト**を作る。単位は概念・主張(エッセンス)であって章ではない。粗くてよい — 勉強しながら割り直せる
3. 記事層を照合する: 各要素について主張行(`articles/*/INDEX.md`)・既存の読書マップの既知マークを grep し、「既知っぽい/未知っぽい」の仮判定を付ける
4. 仮判定付きリストを**一括トリアージ**としてユーザに提示し、自己申告でまとめて修正してもらう(1要素ずつ聞かない)
5. マップを `articles/books/<書名slug>.md` にストックする。初回は `books/` 作成と `articles/INDEX.md` への行追加も行う。コミット: `git commit -m "読書マップ: <書名>"`

マップの形式:

```markdown
---
source: "ISBN:9784xxxxxxxxx"   # 無ければ 書名+版+年
title: "書名"
pdf: "/path/to/book.pdf"       # ローカルパス(コミットするのはこの参照のみ)
started: 2026-07-05
---

# 読書マップ — 書名

- [ ] 転置インデックスの構造 (ch.2)
- [x] TF-IDF — 既知 (2026-07-05)
- [x] BM25の飽和項 (ch.3) — 学習済み → [../information-retrieval/bm25.md](../information-retrieval/bm25.md)
```

状態は3つ: 未着手 `[ ]` / 既知(日付) / 学習済み(→記事リンク)。マップは記事層内で唯一の可変ファイル — 状態更新・要素の割り直しは自由に上書きしてよい。

### B. 勉強セッション(2回目以降の呼び出し)

1. マップを読み、次の未着手要素を提案する(ユーザ指定があればそちら)
2. 該当ページを Read(pages)で読む
3. **既存記事と重なる場合**: 本の内容と既存記事を突き合わせ、差分(新しい知見・矛盾・深掘り)を会話で可視化する。差分の消化がそのセッションの勉強になる
4. 対話で勉強する。ユーザの質問への回答・図の切り出し等は /article の書き方の知見に従う。**確認質問は具体で**: 本の内容をユーザの実務・プロジェクト・コードに当てはめた質問(「あなたのXではこの規律はどこに効く?」)にする。「これは新鮮?」「腑に落ちた?」のような自己内省を求める抽象メタ質問はしない — 理解は具体質問への応答から読み取る
5. 途中で「それは知ってる」となった要素は既知マークにして先へ進む(すり合わせ)
6. **消化した塊 = 1記事**。記事の境界は事前の要素リストではなく、セッションが理解し直した単位で決める。テーマは主題で選ぶ(`articles/INDEX.md` の既存テーマ一覧から提案。**本単位のテーマは作らない**)。ストック判定・実行は /article の手順どおり(「読んで理解した」がゲート)
7. 既存記事の理解が更新された場合は**差し替え**(ADR 0006): 新版を作って差分を提示 → ユーザ判断で同一ファイルを上書き。source: をリスト化して新旧併記、主張行も差し替え、コミットメッセージは「差替: <タイトル>」

### C. セッションの締め

1. マップの状態を更新する(既知マーク・学習済みリンク・要素の割り直し)
2. マップと記事をコミット(記事は /article の手順内でコミット済みなら、マップ更新のみ `git commit -m "読書マップ更新: <書名>"`)
3. 検索インデックスを更新: `curl -X POST http://127.0.0.1:7776/api/reindex`(UI未起動なら省略可)

## 守るべき規約

- **PDFはコミットしない**: マップの front matter のパス記録のみ
- **本単位のテーマを作らない**: テーマ軸は主題であってソース軸ではない。記事は主題テーマに散り、source(ISBN)で緊く繋がる
- **既知要素に記事を書かない**: 既知マークが写像を補完する。バックフィルの義務はない
- **書籍のソースIDは素の表記**: `ISBN:9784xxxxxxxxx`(grep性を保つ。arXiv IDと同じ規約)。章の粒度が要るときは `ISBN:xxx ch.3` と書く
- **マップ以外はスナップショット**: 記事の変更は差し替えのみ。マップだけが可変
