# /article — 記事を起こしてストックする

記事層の規約の正本は `/mnt/ext1/vibe-kanban/impactaky-knowledge/CONTEXT.md`(記事・記事層・テーマ・主張行・ストック)と `docs/adr/0004-article-layer.md`。このスキルはそれを実行手順に落としたもの。

## 手順

### 1. ソースを読む

- arXiv URL → abs ページを WebFetch。数式・詳細が必要なら PDF を取得して読む(PDFはスクラッチパッドへ。**リポジトリにコミットしない**)
- ドキュメント/ブログ → WebFetch(必要ならページを辿る)
- コードベース → 対象を Read/Explore で読解
- ソースのバージョン識別子を必ず控える: arXiv ID / docsのバージョンと取得日 / repo@commit

### 2. 記事を書く(会話上でレビュー)

自己完結で読みやすい読み物として書く。原文を読まなくても理解が再現できること。構成の目安:

- **論文**: TL;DR(3行) / 何が問いか / 主張 / 手法の直感 / 根拠と実験 / 限界・注意 / 自分の文脈との接点
- **ツール理解**: TL;DR / 設計思想 / 仕組み / 基本の使い方 / 落とし穴 / 既存ツールとの違い
- **コード読解**: TL;DR / 全体構造 / 設計判断の読み解き / 罠・歴史的経緯

日本語で書く(コード・専門用語はそのまま)。数式は `$...$`(KaTeX)、図が要るなら mermaid。ドラフトは会話に示し、ユーザの掘り下げ要求に応えて改稿する。

書き方の知見(実運用からのフィードバック):

- **原典の図を引用する**: 説明の要になる図はPDFから切り出して使う(`pdftoppm -png -r 150` でページ化 → `convert -crop` で図領域を抽出 → 表示して切れ具合を確認)。ストック時に `articles/<テーマ>/img/` へコミットし、`![キャプション (Fig N)](img/figN.png)` で埋め込む。記事冒頭に「図は◯◯論文(ソースID)からの引用」と一行明記。PDF本体はコミットしないが、図の切り出しはコミットする
- **寸法感覚の節を早めに置く**: 具体モデル1つ(例: LLaMA3.1-8B)で d, h, k, バイト数などの数値を最初に固定すると、後段の全説明が定量で読める。データ量の収支は表にする
- **対話の掘り下げを本文に還流する**: ユーザの質問(「dって何?」「バッファはなぜ5MB?」)で深まった理解は、ストック前に必ず記事へ反映する。質問が出た箇所=読み物として説明が薄かった箇所
- **確定と推測を区別する**: 原典が明言していること・導出できること・不明なことを本文で書き分ける(「論文の明言は…だけで、導出は示されていない」)。原典が答えていない問いに気づいたら、それ自体を記事の価値として残す
- **ブロック単位で必要性をレビューして削る**: ストック前に各節の必要性を書き出し、主張を支えない周辺情報(命名規則の詳細・原典の表の再掲等)は削除、残す節も圧縮する。simpleが基本(output-style/simplicity.md「必要性の書き出し」の記事への適用)。何を削ったかはユーザに一言示す

### 3. ストック判定を待つ

ユーザが「有用」「ストックして」と言うまで**リポジトリに何も書かない**。却下されたら何も残さず終わる(ドラフトは活動ストリームに残るので失われない)。

### 4. ストックの実行(ユーザ判定後のみ)

1. `articles/INDEX.md` の既存テーマ一覧を見てテーマを提案。合うものがなければ新テーマ名を提案しユーザ確定を待つ
2. `articles/<テーマ>/<kebab-slug>.md` に記事を書く。front matter:

   ```yaml
   ---
   source: "arXiv:2312.00752"        # または "uv docs v0.5" / "repo@abc1234"
   fetched: 2026-07-04
   theme: linear-attention
   ---
   ```

3. テーマの `INDEX.md` に**主張行**を追記(新テーマなら作成): 1記事1〜3行、将来検索しそうな主張だけ。形式は主張文が行頭:

   ```
   - 状態空間モデルはattentionの線形時間近似として機能する — [mamba.md](mamba.md) (arXiv:2312.00752)
   ```

4. 新テーマの場合は `articles/INDEX.md` のテーマ一覧に1行追加
5. コミット: `git commit -m "記事: <タイトル> (<テーマ>)"` — articlesパス配下のみを含める(図の `img/` も含む)
6. 検索インデックスを更新: `curl -X POST http://127.0.0.1:7776/api/reindex`(UIが起動していなければ省略可 — 次回起動時に反映される)

## 守るべき規約

- **スナップショット+差し替え**: 既存記事を勝手に上書きしない。理解が実際に更新されたときの唯一の変更経路は**差し替え**(ADR 0006): 新旧の差分を会話で可視化し、ユーザ判断で同一ファイルを新版で上書きする。source: をリスト化して新旧ソースを併記、主張行も同時に差し替え、コミットメッセージに「差替:」と明記。旧版はgit履歴が保持する
- **PDF等のソースはコミットしない**: front matter の source が正のポインタ
- **決定は記事に書かない**: 記事から得た「従うべき結論」は該当パッケージ(python-practice等)へ通常の蒸留として書き、記事は参照として挙げる
- **記事は読み物**: 箇条書きの羅列でなく、文章として読めること
- **ソースIDは簡潔な素の表記で書く**: `arXiv:2512.03608` のようにID表記のまま書けば、閲覧UIが描画時に自動でリンク化する(裸URLも同様)。markdown正本にリンク記法を増やしてgrep性を下げない。arXiv以外のソースは素のURLをそのまま書く
